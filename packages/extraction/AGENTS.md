# packages/extraction (`@dct/extraction`)

Everything that touches a PDF or a model: page counts, rendering and the text layer (mupdf, in a worker thread), the AI reads that produce a `Rulebook`, the evidence binder that checks every value against the PDF's own text, the deterministic contract checks, and scoring against hand-checked answer keys. No database, no HTTP. The API uses it only through `apps/api/src/extraction/port.ts`. Design: [ADR-001](../../docs/phase-1/adr-001-extraction-evidence.md), partly superseded in stages by [ADR-002](../../docs/phase-1/adr-002-pipeline-redesign.md) (PR 3 is built but off by default); history and limits: [docs/phase-1/extraction.md](../../docs/phase-1/extraction.md). Repo rules: [AGENTS.md](../../AGENTS.md).

| `src/binder.ts` | `bindEvidence` (each value to its spot: confirmed / conflict / ungrounded; unaccounted spans), `reviewFromEvidence` (the questions; a money term's `quoted` lines). Dates are read with `datesIn` from `@dct/shared` (`dates.ts`), the same reader answers are compared with. A single value is confirmed only when its line prints no other amount that could be it, else it's asked. A label matches a row only on a strict majority of its name's words. A conflict consumes nothing on its line or in its quote, so those amounts stay in the sweep; a limit on a fee's line ("up to 3 per subject") stays a term of its own. A rule's figure counts only from a sentence about its term (`ABOUT`). Two grids on one page each bind rows under their own header; one printed row confirms one grid's cells at most. On a page with `grids`, a ruled table that holds the prices is cut into cells (`tableOf`, in the reading frame) and `plan` lines the read's rows up with it in order by the prices each prints, and its visits with the visit columns when their count and headers agree; anything unclean falls back to the label path. Pieces of one drawn table (a header strip, a body in two, extra columns) that touch and share an axis's rules are one table; inside a ruled cell a lone number is a price whatever its format ("150", "45.5"). A row the prices fit by chance (a value of the read on a blank cell, or a printed price at a visit the read leaves empty under a label that isn't the read's) is dropped. A row's printed total confirms the one cell the scan leaves unread, never two. **Held mapping:** when no run's headers agree but none contradicts, and the visit columns line up with the read's visits by count and order (the run the printed columns span), the table's cells that every check would confirm and the label path doesn't are `held` (`ValueEvidence.held` = a `TableCheck` id; status stays `ungrounded`, no printed text) and `bindEvidence` returns `tableChecks`; a row the read gives fewer than two prices must print something in every cell it's given; an "invoiceable" cell inside a held table is held-ok when it prints the row's unit price (OCR digits, conf ≥ 0.8), header or not (a blank cell or another number is not); outside held tables it keeps its rule (the word, or the unit price on a page with its own header). **Rows placed by order** (`place`): in a table whose columns are held or agreed, the read's rows the prices didn't match are placed onto the table's body rows (not blank, not total or subtotal) between two firm rows, or a firm row and the table's end (a header row above the first firm row counts as a body row, so a headed table's start is never placed), when the counts are equal, else left to the label path; their cells are held on the table's check, which lists the rows (`TableCheck.rows`: box and procedure index) for a person's blind row picks. A price match needs the row's label to fit its name at least as well as any other read row's (two rows sharing a word, swapped, no longer match each other's). **Unit price by column:** a row with several costs left of the visits and no visit price to tell them apart takes the unit column the headers name (one cost column that isn't a total or with overhead), unless a cell of the row contradicts the mapping. **Anchors (`bindEvidence(rb, pages, printedRows, anchors)`; `hintsFor`, `plan`'s `hint`):** a procedure's row is the table row most (at least 60%) of its anchored tokens sit in, a visit's column the one most of its tokens sit in; rows must run in print order, two procedures never share a row, columns must all differ and run in visit order, else the table gets no hint and is planned as before. A pointed row is placed there whatever its label and prices say (a cell the scan can't read is the scan's; a cell with no word in it is blank and drops the row). A visit's subtotal, overhead, non-procedure amount or total the labelled-row cascade didn't settle is confirmed at the word the model pointed at when that word says the amount, sits in the visit's own column inside a drawn table, is bound by no other value, and its parts are confirmed and add up (overhead: the stated %). **Cost columns by arithmetic** (`costColumns`, `byCosts`): in a ruled table the column with overhead is the one printing, on rows that print both and differ, the other's price plus the overhead % (the grid's stated one, else the contract's) within a cent (two such rows at least, and most of those that differ); the other is the price before overhead; a table of at most four number columns with one neighbouring pair printing the same on every row is one price printed twice. Never by headers. A unit price is confirmed at the row's cell before overhead, and an invoiceable item or site fee at its own column's cell (OCR digits, every word sure), in the row whose label fits its name best (Dice at least 0.5, better than every other row, and better than any other item's fit to that row; a tie is nobody's); a row so placed whose cell prints another amount is a conflict (the label path never looks at the line's other amounts there, so a quantity printed like a price can't stand in for a price). A planned table's `unitCol` is the arithmetic base column, unless a header names another. **Totals cascade:** a visit's overhead, subtotal, non-procedure amount and total, and a per-patient total, that the label path left unfound are settled from the planned table's labelled row (exactly one; OCR digits, conf ≥ 0.8; the visit's column): a subtotal, non-procedure amount, total or per-patient total must also equal the sum of its parts, each confirmed or held (overhead, a part of the total, is checked on the page alone), never the other way round; confirmed when every part is, held (under the one check they share) when any part or the table's mapping is, else asked. **Visit summary tables** (`summaryPlan`): a drawn table of a visit's page that holds no row of the read but whose rows labelled as a visit's total, subtotal, non-procedure amount or overhead (`VISIT_LABELS`: "overhead at 30%" is overhead; rows about costs "with" or "without" it are not; "per visit" is a total), or whose label the scan lost, print a number for each of the grid's visits (as many columns; one more is accepted when one is the sum of the columns before it on every row printing them all: the table's own total) is planned as if a row had been: the columns are the visits' by count and order, held (a table check) unless the headers agree, none when they contradict. A visit's overhead must also be the grid's stated % of the read's cells of the overhead-applied rows at that visit (within a cent for every two of them); an overhead row whose label was lost is the one unlabelled row printing that at every visit it prints (three at least, most of those with overhead). A continuation page rides on an earlier check of its grid when its visit columns' rules are within 3 pt, else it has its own. `reviewFromEvidence` asks one `TABLE_CHECK` question per check and none per held cell. **Blank "invoiceable" cells** (`blankInvoiceable`, `bindEvidence`'s `blankChecks`): in a planned table (rows from the plan or placed by order), a read cell whose value is "invoiceable" where the drawn cell holds no word and no unread ink, on a text page or a clear OCR page (70% of its words at conf >= 0.8, as `reviewDraft`'s `clear`), is marked `blank: <check id>` (status unchanged) and grouped per table; a cell that prints anything, or on an unclear page, stays as it was. The API asks one `BLANK_INVOICEABLE` question per group (not per cell). On a table whose mapping is held the group carries that table's check (`BlankCheck.after`) and waits for it. A person's answer flow comes later; until then a held value blocks sign-off. the old scan gate counted held as confirmed for every gate **OCR noise candidates** (`src/candidates.ts`, `ocrCandidates`): on pages with `source === "ocr"` only, never a PDF's own text, a read value matches a word when it is among the cents the word may mean ("185,00", "47:00", "172-00", "4.070.00"; the guide's "4500" as 45.00 and a "$" read as 5, "526" as 26, are off by default, one switch from on); applied at every comparison of a read value to a word (`readOf`, `says`, `saysAmount`), while arithmetic and what makes a word a clean price stay on the plain parse, so a clean price matching no candidate is still a conflict. A candidate-only match is confirmed with `note` "the scan's digits were read allowing for its usual misreadings". The leading-5 rule, when on, needs three digits or more and skips a word ending in a two-decimal fraction; it gained no confirmed value on any scan, so `OFF_BY_DEFAULT` holds it with the lost-point rule; each rule is switchable in `RULES` **Total columns (`geometryTotals`, `plan`):** a total column is any column that is no visit's, no unit price and not left of the visits, wherever it sits: right of every visit, or between the scheduled visits and conditional ones (unscheduled, early termination) printed after it, which are then outside the row's sum (`RowBand.covers`). Once found, every body row that prints a total the scan is sure of has it, a row with a cell the scan can't read included (the total is what says what that cell is). Quantity times unit price finds it too, from rows whatever their visit cells make of it. On a page with no header of its own (a continuation) `plan` takes the cost columns by the page's arithmetic (`costColumns`) as left of the visits, and a column that is, on most rows, the sum of the visit columns before it (`totalCol`) is the table's own total, not a visit. **Rows (`RowBand`, `bindEvidence(...).rows`):** each rulebook row placed in a planned drawn table, with its row box across the table's width, one cell box per visit column, and `total`/`by`: what the table prints as the row's total, from its own geometry (`printedTotals`: a column right of the visits that is the sum of the row's printed cells, sure OCR digits, on at least two rows (one with two cells) and most of those that print it; else a quantity column left of the visits equal to the count of populated cells, times the printed unit price; a totals row is no body row); null when the table prints neither. The solver's row identity and the sweep's row bands read it | **Round 3 (ADR-002 §10):** `RowBand.covers` (the visits a printed total covers; the total column is also found by printed quantity x unit price, a quantity printed "22.00" counts), `RowBand.cells[].ink`, `bindEvidence(rb, pages, printedRows)` (the grid read's `printedQty` / `printedRowTotalCents`, taken only where the scan prints the same figure in that row); the solver's `rowUnit` identity, its `vetoed` count and its `rounding` option (off); the sweep's `column_vouched`, `price_count` and `overhead_pair` drops.
| `src/solver.ts` | `solveGrids(rb, evidence, { mode, rows })` (ADR-002 PR 2): the document's own arithmetic as a referee. Identities: an invoiceable's price with overhead against its price and the overhead %; **a row's read cells against the total the PAGE prints for that row** (`RowBand.total`, from `bindEvidence(...).rows`: a total column right of the visits whose printed value is the sum of the row's printed cells on at least two rows and most that print it, or, with no such column, a printed unit price times a printed quantity column that equals the count of populated visit cells; found from the drawn table's own OCR/text, not the read; a table that prints neither has no row identity, so none of its visit cells is ever confirmed by math, and a row with an "invoiceable" cell has none); a visit's cells against its subtotal plus non-procedure amount; a visit's overhead against the % of its overhead rows; subtotal + overhead + non-procedure = total; a per-patient total against the visit totals. Upgrades `conflict` and `ungrounded` entries to `confirmed_by_math`; never touches confirmed, attested or held entries (held ones that would pass are only counted); unit prices are in no identity. **Tolerance by operation:** addition (row, column, visit total, per-patient total) is exact on a grid whose figures are whole dollars and 5 cents on one that prints cents (`printsCents`: more than one figure in twenty is not a whole number of dollars, grid by grid; a row reads it from the page's printed row totals); multiplication (overhead, item and visit) is 5 cents where the target column prints cents and, where it prints whole dollars, the expected figure rounded to a dollar may differ from the printed one by a dollar. The report holds counts and JSON pointers, never text |

## Rules

- Only `src/llm.ts` builds a model client and calls a model, and only contracts go to it. (`src/model-schema.ts` imports the Anthropic SDK's schema helper, which makes no call.) `test/llm.test.ts` fails if `apps/*/src` or `packages/shared/src` imports an SDK.
- Every image sent to a model passes its page's bank mask (`masks` in `extract.ts`); every reply goes through `sanitize`/`scrub`. Add a new image path the same way. No error message, warning or log line quotes a model's reply.
- In a read, the abort signal and the spend cap are checked before every model call through the `capped` clients; don't add a call that bypasses them. (`identifyDocuments`, at most 3 pages per document on the fast model, isn't capped and its cost isn't recorded.) Each call's output is bounded by its kind (`CONFIG.maxOutputTokens`).
- Page and image limits are checked before anything is rendered or sent. Keep new work behind them.
- In force (ADR-002 PR 1, not yet run on a real contract): pages the classifier calls `esign_certificate`, `esign_disclosure`, `reference_appendix` or `non_content` go to neither the terms read nor the grid reads, and `reviewDraft` drops their leftover-money spans; a `pages_excluded` warning lists them (`excludedPagesWords`). `boilerplate` is still read and swept. The label decides, so a page with money mislabelled as one of the three is not read: the warning marks pages whose own text prints an amount.
- In force (ADR-002 §9): `isNonContent` (`extract.ts`) marks a blank separator or cover sheet `non_content` from the page's own words (PDF text, or our OCR's where it ran; never a scanner's layer, never a new OCR run), whatever the classifier said; conditions in its comment, and unsure pages are read. It is an excluded kind like the three above: not read, not swept, listed in the `pages_excluded` warning, and a scan page of it asks no `SCAN_PAGE` question.
- In force (ADR-002 PR 2): `confirmed_by_math` (`solveGrids`) and the zone-gated sweep (`gateSweep`), both run by `reviewDraft` after the binder, in that order, then the questions; the API setting `EXTRACTION_SOLVER=guide|strict` (default strict since 2026-10-31: the guide's own `guide` mode let wrong visits and swapped rows through, ADR-002 §3(b)) picks the solver's mode (the two now differ only in the "no overhead applied" acceptance, see `src/solver.ts`; the tolerances and the both-identities rule are every mode's), and the offline scan gate that measured it (`ocr-eval`) was removed with its four test contracts (ADR-003). `reviewDraft` hands the solver and the sweep the binder's `rows`; the numbers in ADR-002 §3(b) predate the page-printed row identity and the row-band sweep and are re-measured, not carried over. Measured results per mode: ADR-002 §3(b). A value that cites no page is never upgraded (the wiring keeps it as it was and counts it). Grids are tiled as above unless `EXTRACTION_BANDS=1`.
- **Switch (ADR-002 PR 3; off by default; the row bands, `EXTRACTION_BANDS`, were removed by ADR-003 C3).** `EXTRACTION_TOKEN_MAP=1` (`CONFIG.tokenMap`): the text/OCR pass (read once, with the bank masks) goes to the model beside each grid tile, **never a terms or invoiceables page**, as a token map, and the grid read (`AiGridsAnchored`) returns `source_token_id` per cell and per visit sum (`visitTokens`) and the amounts it is sure are no fee (`nonFee`: token id and a reason). An id not in that call's map is dropped after parsing; the kept ones come back as `ExtractionOutput.anchors` (`Anchor`: grid, page, word index, field, visit, procedure) and `ExtractionOutput.nonFee`. **A word that holds a number is sent to the model as "#" (`tokenText`, `llm.ts`)**: the model reads every figure from the image, so its value stays independent of the OCR's digits, and the map only says where words are. The binder uses the anchors for *where*, never for *what* (see the binder row): a row is placed in the table row most of its tokens are in, the visit columns are the ones its tokens are in (when every visit has one and they run in visit order, the table is not held), and a visit's own sum is read at the word the model pointed at. The value is still judged against what the cell prints, and the solver's arithmetic carries confirmation. A `nonFee` mark is believed by the sweep only where a rule of ours agrees (`gateSweep`: a code or page number printing no currency mark, cents or thousands comma; a repeat equal to a price the master holds); anything else it calls no fee stays asked and is counted (`modelKept`). Tokens skip bank areas and any word that scrubs differently; only pages of the PDF's own text or our OCR give tokens (a scanner's text layer has no bank mask). Token text is contract text: it goes out only through `llm.ts` (`tokenText`) and never into a log, an error or a warning. Terms values are not anchored and their pages carry no map (not built; the owner approved it, ADR-002 §10).
- OCR text is contract text: never logged, printed or put in an error (the worker reports errors by class name only). The worker gets no network and no secrets; keep it that way.
- On an OCR page a blank, garbled or unsure (conf < 0.8) cell says nothing, and an "invoiceable" cell is confirmed only by the word: a printed price in it confirms nothing (planted wrong-visit errors passed that way). Visit columns must run in visit order.
- Text that no reader can see (`hidden`) is never evidence.
- No prompt or check may name a sponsor, CRO, drug, procedure or layout taken from a specific contract (ADR-001 §8).
- Never log or print contract text or amounts. The scripts print counts and scores only.
- `src/` loads no `.env`: the API process provides the environment.
- Changing an export means changing `ExtractionPort` in `apps/api/src/extraction/port.ts`. The API maps `ExtractionLimitError` and `RenderTimeoutError` to messages by class name (an upload whose page count times out is a 422), so keep those names and keep their messages plain English. A new `ReadWarning` kind fails the API's typecheck until `plainWarnings` words it.

## Pitfalls

- `mupdf-worker.mjs` is plain JavaScript on purpose: it runs as is under tsx, vitest and the API's bundle. It's found through this package's `exports` (`@dct/extraction/mupdf-worker`), because the bundle has no file beside it. Keep both.
- `fixtures/fake-extraction.json` is imported, not read from disk, for the same reason.
- Model ids and prices are in `src/llm.ts`. Defaults: `claude-sonnet-5-5` reads, `claude-haiku-5-5` sorts pages and identifies, Haiku re-reads terms (`CROSS_READ`). No Opus (cost decision, 2026-10-26).
- The four image-only test contracts were deleted (ADR-003, 2026-11-01): the client's contracts are native DocuSign PDFs. The signed COPD work order is the native test contract; one layout, so a new sponsor's layout is measured before it's trusted (the arithmetic guard makes an unknown layout fall back to the model's read, never pass wrong).
- The second read (`CROSS_READ`) and `LOW_CONFIDENCE` still run, but the API never asks about them: they are not evidence. ADR-001 plans to remove them.
