# ADR-002: A new extraction pipeline: OCR first, the model anchored to it, arithmetic as the referee

**Status:** Accepted by the owner (Prateek), 2026-10-31. **Built in stages:** PR 1 and PR 2 are in the code (§2, §3(b)); PR 3 is built behind switches that are off. The floors (§4) and the page and check rules of §9 are in force. Until a PR lands, the code still enforces the rules it supersedes (§2). **Supersedes, in stages:** parts of [ADR-001](adr-001-extraction-evidence.md) §3, §4 and §6, as listed in §2. Everything in ADR-001 not named here stands.

**Input:** an engineering guide from a senior engineer (outside the repo; it is built on real contracts, so nothing from it is copied here). Its design is adopted as the direction. Its numbers are not: see §3(f).

---

## 1. Decision

The pipeline keeps its shape (read, check, ask, sign off) and the rule behind it: **no silent errors**. What changes is how a value gets confirmed, and how many questions that costs.

1. **The text or OCR pass runs first.** Every page gets an indexed token map (token id, text, box) before the model reads it. The model gets each image together with the tokens inside it, and returns each value with the id of the token it read it from (`source_token_id`). The model reads the image; the token only anchors where.
2. **The document's own arithmetic is a referee.** A solver checks, on the extracted grid: a price with overhead against the price without it and the overhead %; **a row's cells against the total the page itself prints for that row**; a visit column's cells against its subtotal; a visit's subtotal plus overhead and other parts against its total. A value that takes part in identities that all balance is `confirmed_by_math`, and a visit cell needs **both** a row identity and a column identity (the senior engineer's "and" decision, replacing the guide's "row or column"). Three rules from his review, owner-accepted:
   - **The row identity is the page's.** It exists only where the table prints an explicit row total (a column right of the visits whose printed value is the sum of the row's printed cells on at least two rows and on most rows that print it) or an explicit quantity (an integer column equal to the count of populated visit cells, times the printed unit price). The binder finds it in the table's own OCR or text geometry (`RowBand.total`), and the read's cells are compared with that printed figure, never with the read's own sum. The old identity (unit price times the read's own count of cells) is removed: on a flat price it is a tautology. Where a grid prints neither (some print only a "cost per" and the visit columns), no visit cell is ever upgraded by math, because a column sum alone can't say which row a number belongs to; visit-level values (subtotal, overhead, non-procedure amount, total) still can be, by their column and visit identities. The rulebook has no row-total or quantity field and none was added.
   - **Tolerance depends on the operation.** Addition and subtraction (row, column, visit total, per-patient total): exact on a grid whose figures are whole dollars, 5 cents on one that prints cents. Multiplication (the overhead identities): 5 cents where the target column prints cents; where it prints whole dollars, the expected figure rounded to a dollar may differ from the printed one by a dollar. "Prints cents" is decided from the grid's own values (more than one figure in twenty is not a whole number of dollars), grid by grid for addition and column by column for overhead; a row identity reads it from the printed row totals. A printed figure with more than two decimals (a raw unrounded float) can't be held in integer cents: the read holds it rounded, so its grid reads as a cents grid and keeps the 5 cents.
   - **Two modes, one difference.** `strict` (default) and `guide` now share the tolerances and the both-identities rule; `guide` alone also accepts "no overhead applied" (price with overhead equals the price) beside a figure that is already confirmed or attested. The guide's flat 5 cents, "any one identity" and flat-price-fill leniency are gone, so there is nothing else to separate the modes; `EXTRACTION_SOLVER` keeps both names (they collapse to one mode if the owner drops that acceptance).

   Guards in both modes: a value whose printed text is a whole price is never overridden by sums; "no overhead applied" confirms only beside a confirmed or attested figure; a per-patient total confirms only on the sum of every visit; a value that cites no page is never upgraded; a unit price is in no identity, so math never upgrades one.
3. **Pages with no money terms are not read.** The page classifier marks signing certificates, e-signature disclosures and non-financial reference appendices (such as drug code lists). Those pages go to neither the model nor the leftover-money sweep.
4. **The sweep is zone-gated.** Cells already consumed by a confirmed grid are never flagged, and once a drawn table's row is lined up with a rulebook row every number in that row's band, across the table's width, is its (a price in a visit cell the read has no value for stays asked unless that visit's column adds up to a printed subtotal the page confirms; a row no rulebook row took, and a number outside the table, are still flagged); there is no page-level gate that sweeps only grid pages, because terms pages hold the holdback, the net days and the start-up fees and "no holdback" is found by sweeping them and finding nothing; insurance and indemnification clauses are excluded; on narrative pages only an amount with a currency mark, or near a financial trigger word, is flagged; and an amount printed in a table (a summary table repeating the visit totals, a Totals column) that equals an amount the master already holds is not asked again (`explained_by_master`, the guide's summary-versus-detail cross-check).
5. **Dense grids are cut into row bands, each with the table's header attached on top, instead of blind square tiles.** A later PR, and it needs live reads (§5).

The goal is fewer questions with the same guarantee that a wrong number is never approved without someone seeing it. Whether the guarantee still holds is the question §3 answers honestly, and the owner has accepted it.

## 3. Consequences

Stated plainly, because the design trades something real for fewer questions.

**(a)** Removed by the owner (2026-10-31).

**(b) The solver can confirm a number in the wrong place.** The guide's reference solver confirms a cell when its row or its column balances. A number put in the wrong visit still balances its row. ADR-001 §4 already says arithmetic cannot catch swapped cells. The owner has been told this. The planted-error gate (`pnpm --filter @dct/api ocr-eval`) stays as the **measurement** instrument: after every PR we report the number of wrong values confirmed and the planted errors caught. It is reported, not a blocking rule. Decided after the first measurements below, on the senior engineer's review: a visit cell needs both a row and a column identity in every mode; the row identity is the page's own printed row total or quantity, never the read's own sum (§1(2)); a table that prints neither confirms no visit cell by math; tolerances are by operation (§1(2)). **The tables and counts below were measured before that change and are history, not the current state: the planted-error classes, the questions per contract and the values upgraded by math are to be re-measured with the final rules (no new numbers are claimed here).** Expect fewer values upgraded by math on tables that print no row total, and the wrong-visit and row-swap classes to depend on whether the table prints one.

*Measured in PR 2 (`ocr-eval` on the four scans, both modes, against the baseline before PR 2; counts only).* "Before fixes" is the first wiring; "after fixes" adds four guards found in review (the sweep consumes only what a bound value claims; a whole printed price is never overridden by sums in guide either; a row's sum needs a backed unit price and "no overhead applied" needs a backed figure; a per-patient total confirms only on the sum of every visit). Values wrong against the answer keys stayed 0 in every run. Planted errors let through, summed over the four contracts (denominators grow with the values the arithmetic confirms; the baseline let through 0 of every class):

| digit (look-alike) | 34 / 6963 | 6 / 6708 | 21 / 6631 | 13 / 5898 |

Questions per contract (COPD, HCWC, McAllen, Shah): baseline 82, 318, 258, 84; guide before 71, 215, 91, 61, after 77, 284, 100, 77; strict before 74, 259, 88, 64, after 76, 287, 136, 77. Values upgraded by math: guide before 5, 56, 157, 4, after 0, 11, 153, 1; strict before 1, 13, 157, 1, after 1, 9, 114, 1. Sweep spans dropped as consumed: guide before 65, 325, 50, 38, after 60, 211, 0, 9; strict before 68, 324, 81, 38, after 63, 208, 31, 9 (insurance clauses: 4 on one contract; none dropped for a missing currency mark). The scan study replayed on the restored copy of the dev database (84 questions at baseline): guide 58 then 73, strict 61 then 73 (leftover money terms 45, 23, then 35); values upgraded by math 4 then 1 (guide), 1 then 1 (strict).

What still got through at that measurement, for the owner to decide (the default is **strict**, switched by the lead on 2026-10-31 after these numbers; `guide` is now strict plus one acceptance, §1(2)): **guide** lets through a price copied to a visit the row doesn't print (the row's own sum still balances), row swaps and a summary row read from the next visit (a column sum survives a swap of whole rows; a summary figure's parts still add up), and some compensating errors; **strict**, which also needs a column to balance, lets through only the cases where rows exchanged leave every sum unchanged, the summary row on one contract (36), and digit errors smaller than the rounding tolerance on contracts that round to the dollar (McAllen: 6 and 13). Guide's flat 5 cents also fails overhead identities on contracts that round to the dollar, which strict's rounding tolerance passes (one contract, before the fixes: 0 of 25 against 25 of 25). The decimal-point class is not the solver's: the 55 (COPD) and 28 (McAllen) values that pass in strict are binder-confirmed against a printed whole price of three digits ("450", "$450") that the missing-point candidate rule (`candidates.ts`) also reads as 4.50, so a value 100 times too small matches; the rule was not changed.

**(c) OCR noise candidates widen what confirms.** (Final state: the leading-`5` rule (a `$` read as 5) and the missing-point rule ("4500" is also 45.00) are both **off by default**, one switch from on in `OFF_BY_DEFAULT`; the narrowing below applies if the leading-`5` rule is switched on. Only the decimal-separator and dot-thousands rules are on.) Reading a leading `$` as `5`, a decimal point as a comma, colon or hyphen: accepting those as candidates lets more model values match their token, and lets some wrong ones match too. Each PR reports how many values the candidates alone confirmed and how many of those were wrong.

*Measured in PR 1b (`ocr-eval` on the four scans, against the baseline taken before the change).* With the guide's four rules as written, the candidates confirmed 3 more values in all (HCWC 1 from the decimal rules, McAllen 1 from the thousands rule, none from the leading-`5` rule) and let 15 planted digit errors through (COPD 12, HCWC 2, Shah 1), all from the leading-`5` rule; values wrong against the answer keys stayed 0. Narrowing that rule to words of three or more digits that don't end in a two-decimal fraction (every example the guide gives still works) brings every planted gate back to the baseline (COPD 1869/1869, HCWC 1065/1065, McAllen 1398/1398, Shah unchanged, the denominators growing with the extra confirmed values) and keeps the +3 confirmed values (HCWC 602 to 603, McAllen 467 to 468, 2 fewer questions on McAllen, 1 fewer on HCWC). The rule stays switchable in `candidates.ts`, and was then turned off by default: with the narrowing it gained 0 confirmed values on every scan with our OCR (owner's decision on the senior engineer's review: no dead heuristics). A candidate-only match is traceable: its evidence `note` says the scan's digits were read allowing for its usual misreadings.

*Measured in the final run (the new decimal-point planted class).* With the missing-point rule on, a printed whole price ending in `00` confirmed a read one hundredth of it, and the planted decimal-point error got through 81 times on COPD and 52 on McAllen (the solver was not involved). The rule had gained no confirmed value on any contract, so it is off by default (`OFF_BY_DEFAULT` in `candidates.ts`, one switch from on); with it off every decimal-point planted error is caught again.

**(d) A mislabeled page is never read.** A page the classifier calls a certificate, a disclosure or an appendix, and which holds money terms, is neither read nor swept. An empty field (no holdback, no cap) can then pass, because ADR-001 I4 relies on the sweep finding nothing. PR 1 records the excluded pages in the version and shows them to the reviewer and approver. Whether a person must confirm an exclusion is not decided; PR 1 reports how often the classifier is wrong on the saved reads first.

**(e) The model should not predict the header's edge.** The guide has the model return the y coordinate where a table's header ends. That is the same pixel prediction the guide distrusts in the old design. The band PR takes that line from the OCR's table geometry (the ruled table the binder already cuts, `tableOf`) and uses the model only for the column meaning.

**(f) The guide's question counts are not requirements.** Its targets (0 to 5 questions per contract) were estimated without our code. We report the measured count per PR and per contract, and don't hold a PR to the guide's figures.

**(g) A failure that exists today, unrelated to the guide.** Measured on one real scan: our OCR drops the last digit of condensed prices, about 26% of the price cells on that page, at a confidence of about 0.92. Confidence does not flag it. It is fixed in PR 1, and the replay and `ocr-eval` numbers before and after are recorded. (Measured on 2026-10-31 from the saved OCR reading of one real scanned page: 64 of about 245 amounts lost their last character, at a mean confidence of 0.92.) **Root cause, found by the OCR investigation:** not clipped boxes, but the engine shrinking the whole page: `Global.max_side_len` defaults to 2000, so a 300 DPI page (3300 px) was read at about 180 DPI, and on condensed type the recogniser collapsed repeated characters (31 of 44 truncated amounts on the page were the full amount with each run of repeated characters collapsed to one). Padding the boxes made it worse. The fix sets `max_side_len` to 4200 (truncated amounts on that page 44 to 3). The same investigation found the engine's text-line angle classifier doing harm: on 95 scanned pages from five contracts it flipped short numbers upside down (`930.00` read `00006`) and lost about 750 words of one contract's text; with it off no complete amount changed and 17 more were found. It is off, and a trailing `|` from a table rule at a cell's edge is stripped. Cost: peak memory about 3.2 GB (was 2.6), and OCR takes somewhat longer per page.

## 4. The floors, as decided

ADR-001 §6 asks every contract for a blind sample of 10 confirmed values and the interpretations. The owner decided with the senior engineer (2026-10-31):

- **The blind sample of 10 stays.** With more values confirmed by arithmetic and by OCR anchors, a person typing blind from the page is the one channel that depends on neither the OCR, the model nor the arithmetic; it is also how silent errors are measured on live contracts (ADR-001 §6, §10). A sample of 0, or of 5, was weighed and not chosen. The values no longer asked as interpretations are eligible for the pool.
- **Interpretations are asked only for genuine ambiguity or silence.** Two tiers:
  1. **Explicit terms are not asked.** A clause states a deterministic parameter outright (a payment window in days, a holdback percentage, a named kind) and the read gives the clause's exact quote and the binder confirmed the value from the page (`confirmed` or `confirmed_by_math`). The value is extracted with its quote and joins the pool the sample draws from; no open-ended question is asked. Payment days, holdback % and the like were never interpretation questions (they are values: confirmed, or typed when not). What this changes is the interpretation list.
  2. **Genuine ambiguity or silence keeps its question:** an `AMBIGUOUS_TERM`, a `RETROACTIVE_NO_DATE`, a field the read leaves `unspecified`, the screen-failure terms (their kinds depend on a condition), and any field nothing confirms.
- **The rule for "explicit and confirmed" is mechanical** (`interpretations`, `packages/shared/src/questions.ts`; the API's `reviewDraft` and the sample server pass the evidence): the read gives a value other than "not stated" and cites the clause's exact words; the figure that decides the field is `confirmed` or `confirmed_by_math` in the evidence (the binder confirms a figure only inside that quote, on the cited page, in a sentence about the term); no `AMBIGUOUS_TERM` or `RETROACTIVE_NO_DATE` is about the field. It holds today for: an invoiceable's cap kind when it is **amount** (its limit is a confirmed dollar figure) or **ratio to randomized** (its ratio is confirmed), and the start date when it is given and confirmed. A count or "blocks" cap is told from a ratio by nothing but its wording, so it is still asked; the screen-fail cap and every other field are still asked: overhead scope, how visits are paid, a site fee's trigger, the screen-fail basis and payment, the holdback's scope, rounding. The binder confirms no word of an enum, so nothing deterministic says the clause stated it outright. Extending the rule to those means confirming a named kind from its quote, which is language judgment: not done, and the owner's to decide.
- **What the sample doesn't cover.** An unasked cap kind has no evidence entry of its own, so the sample draws its figure, not the kind. The kind is protected by the figure's type (a dollar figure in the quote) and by the sample of the figure.

### PR 3 status: built, OFF by default, UNVERIFIED on a real contract

Built behind two switches, both off, so today's reads are unchanged (the tests assert the same images and prompts with them off). Nothing here has run against a model or a real contract: the tests use synthetic PDFs and mocked clients.

- **Removed (ADR-003 C3, 2026-11-01):** the row bands. P2 reads grids from the PDF's text by code, so no grid image is cut at all. What follows is the record of what was built. - `EXTRACTION_BANDS=1`: row bands with the header stitched on top of each (`bands.ts`, `renderBands`). The geometry is the page's own words, not the model; a page it can't band keeps its tiles and a warning names it. **Revised after the senior's answer (2026-10-31):** a band is the table's full width at one DPI, capped at **3500 px** (it was 2400; one DPI-equivalent of an 11-inch landscape sheet at 300 DPI, inside the senior's 3300 to 3600; chosen, not measured), and holds at most 12 rows and **600 px of body rows** (the senior's 400 to 600) plus the stitched header. The fallback to tiles (`size`) now applies only when even that width can't make the small print readable: `bandMinWordPx` (14 px, the old figure kept, chosen not measured) counts a word's height **as the model sees it**, after Claude shrinks an image past 2576 px on its long edge (`bandViewPx`). That is a doubt, not a gain: a band wider than 2576 px is shrunk by the provider, so 3500 gives a sharper render of the same page, not more pixels per point in what the model reads. Whether the wider cap helps is the first thing a live run shows.
- `EXTRACTION_TOKEN_MAP=1`: the text/OCR pass runs before the model reads, and each **grid band and tile** (never a terms or invoiceables page) goes out with its token map; the grid read may return `source_token_id` per cell and per visit sum, kept only if it is in that call's map. In this PR the ids are only kept (`ExtractionOutput.anchors`): the binder and every evidence status are unchanged, and the solver's arithmetic still carries confirmation. Terms values are not anchored and see no token map.
- `maxTilesPerExtraction` is 120 (it was 60), whatever the switches.

**What the owner must approve to measure it** (a budget first; each step is a live read of named contracts, never run by an agent without that approval): (1) one `pnpm probe` (a live schema check, a few cents; it may need extending to the anchored grid schema), to confirm the API accepts `AiGridsAnchored` (it adds one optional field and one optional list; the union count is unchanged); (2) `pnpm eval <contracts>` with `EXTRACTION_BANDS=1`; (3) the same with `EXTRACTION_BANDS=1 EXTRACTION_TOKEN_MAP=1`. Compare each against the saved run with both off, per contract: questions raised, wrong values confirmed (must stay 0), planted errors caught (must stay all), `GRID_CONFLICT` and `VISIT_TOTAL_MISMATCH` counts, grid cells matching the answer keys, cost in dollars (a token map adds input tokens), how many pages fell back to tiles and why, and how many `source_token_id` the model returned against how many were dropped as unknown. Turn a switch on by default only on the owner's say-so, and then update the `packages/extraction/AGENTS.md` rule about the text layer.

## 6. How each PR is measured

- **`ocr-eval`** (`pnpm --filter @dct/api ocr-eval`; `data/` and the local OCR, no AI): wrong values confirmed, planted errors caught, questions per contract. It counts held values as confirmed. It reports; it doesn't block.
- **The replay script** `apps/api/scripts/replay-study.ts` (written by another agent): runs the pipeline's no-AI steps on a saved read. It opens the dev database read-only (one connection, `default_transaction_read_only=on`, SELECT only), so it never writes and never starts a worker; run it with `pnpm --filter @dct/api replay <studyId> [version] [--json <path>]`. Prints counts only. A version a person has already answered differs from what was first read (an answered value is `attested`), and a by-hand version with no read has nothing to replay.
- **Reported after every PR:** questions per contract (measured, not the guide's targets); wrong confirmed values and planted errors caught; values confirmed by candidates alone and by math alone; excluded pages, and any with money terms on them.
- A live eval is never run without the owner's approval and a budget.

## 9. Smaller rules decided with the senior (2026-10-31)

- **A duplicate is one procedure twice in one table.** `DUPLICATE_ITEM` no longer flags a priced grid cell that matches an invoiceable item: a scheduled-visit price in the grid and an unscheduled or repeat price among the invoiceables is standard budgeting. It flags the same procedure on two rows of one grid priced at the same visit, or the same invoiceable listed twice.
- **A parent agreement missing from an amendment is one question.** An amendment uploaded without the agreement it amends raises one non-blocking `MISSING_REFERENCED_DOC` that names the agreement and lists everything the read says is referenced and missing, instead of one per document. Other documents keep one each.
- **Blank separator and cover sheets are not read.** A page of the PDF's own text, or of our OCR's words where the OCR ran, with fewer than ten words outside the header and footer, no digit, no money word or sign, no table, large picture, hidden text or unread ink is excluded as `non_content`, shown in the same `pages_excluded` warning as the other kinds. Unsure pages are read. No OCR run is added for it.

## 10. Round 3 (senior engineer's second reply, 2026-10-31): code-only part, measured on the saved reads

Built, in force, measured with `pnpm --filter @dct/api ocr-eval` (strict, no AI):

- **The total column is found by quantity x unit price.** A quantity prints as "22" or "22.00"; a column right of the visits (and that is not the unit price, the quantity or a visit) whose printed value equals quantity x the printed unit price on at least two rows and most that print one is the row total, whatever the row's cells add up to (`geometryTotals`, `binder.ts`). `RowBand.covers`: the visits left of that column; the row identity sums only those. The columns right of it (an unscheduled or early-termination visit, a pregnancy) are held as visits by the read and are checked by the new `rowUnit` identity.
- **`rowUnit`** (`solver.ts`): where a table prints no row total (or for the cells a total leaves out), a row's priced cells that all equal its backed unit price and each sit on printed ink (`RowBand.cells[].ink`) are placed; the cell confirms only beside a column that adds up to a subtotal the page backs (`vouched`).
- **A cell is no better than its column.** A cell the binder confirmed from its row's line alone (no drawn-table geometry, so no visit) is taken back (`vetoed`) when its visit's column fails against a subtotal the page backs. Cells placed in a drawn table are exempt.
- **The model's own printed quantity and row total** (`printedQty`, `printedRowTotalCents` on the grid read's rows; never in the rulebook): `ExtractionOutput.printedRows` -> `bindEvidence(..., printedRows)`. A claim is used only where the scan prints the same figure in that very row (a total right of the visits, a quantity left of them, with a sure unit price), and only for rows the geometry gave nothing for. Not run live: the schema change needs `pnpm probe` and a live read, both of which spend money.
- **Sweep, label-independent rules:** an amount inside a mapped table, in a visit column the page's subtotal vouches for (`column_vouched`); an amount the page prints K times when K of the read's values equal it and cite that page (`price_count`); a table line printing a master price and the master's price with overhead (`overhead_pair`). Each is counted in the audit's `explainedBy`.
- **A failing per-patient total still holds back the visit totals it sums, except** where the grid has another per-patient total that adds up over every visit (a total over some visits only, such as a screen-fail path, is no sign a visit total is wrong).

Not built, awaiting the senior: the **rounding-aware tolerance** (`SolverOptions.rounding`, `OCR_EVAL_ROUNDING=1`, off). A visit total printed in whole dollars over parts that print cents, and a per-patient total over visit totals each rounded on its own, are accepted within less than a dollar per visit total and half a dollar per visit for the patient total. On McAllen it takes 148 questions to 89, but 6 planted summary-row shifts then pass; with the visit-total part alone it is 115 with 4 planted digit errors passing. The planted-error gate fails, so it stays off.

Measured (questions, saved reads, strict): EFC18243 48 -> 46; CBT-CS301 43 -> 43; MVT-601A-006 198 -> 197; BHV3000-315 150 -> 148. Wrong values confirmed: 0 on every contract. Planted errors: unchanged (EFC18243 costColumnSwap 115/117, MVT-601A-006 rowSwap 194/196, CBT-CS301 columnShift 4/7).

## 11. Round 4 (owner's cooperative-pipeline directive, 2026-10-31): the model's pointers, measured

The owner overrode the "OCR and the model never see each other" rule of ADR-002 PR 3 and ADR-001 §4 **for grid reads**: the text/OCR pass runs first, the model gets its token map beside each grid image, and returns where it read each value. Independence is kept a different way: **a word that holds a number reaches the model as its shape (every digit a `#`), never its digits**, so the model's figure is its own reading of the image and the binder's comparison with the OCR's digits at the pointed word stays a comparison of two readers. Terms, invoiceables and site-cost pages still get no map and no pointers (the owner approved them; not built).

Built (extraction, no database change):
- **Token map** (`tokenText`, `llm.ts`): the image's printed lines top to bottom, each `[y0, y1, [id, text, x0, x1], ...]`. A first version (a flat list of `[id, "#", x0, y0, x1, y1]`) was sent on a live read of one contract and the model returned no pointer at all; the line layout with digit shapes was then tried on one grid page and returned a valid id for all 129 cells, all 22 visit sums, and every pointed word's OCR text equalled the model's value.
- **Grid schema** (`AiGridsAnchored`): `source_token_id` (id or null) on every cell, `visitTokens` for a visit's subtotal, overhead, non-procedure amount and total, and `nonFee` (token id and a reason from a fixed list). `ExtractionOutput.anchors` (`Anchor`: grid, document, page, word index, field, visit, procedure) and `.nonFee`.
- **Binder** (`bindEvidence(rb, pages, printedRows, anchors)`): the pointers say *where*, never *what*. A procedure's row is the table row most of its tokens are in (at least 60%), a visit's column the one most of its tokens are in; rows in print order, no two procedures on one row, columns all different and in visit order, else no hint. When every visit has a column the table is not held (no count-and-order guess, no table check). A visit's own sum the labelled-row cascade didn't settle is confirmed at the pointed word when that word says the amount, sits in the visit's own column, is bound by no other value, and its parts add up (overhead: the stated %).
- **`geometryTotals` and `plan`, generic:** a total column is any column that is no visit's, no unit price and not left of the visits, wherever it sits (between the scheduled visits and conditional ones too); once found, every body row printing a sure total has it, a row with a cell the scan can't read included. Quantity times unit price finds it from rows whatever their visit cells make of it. On a headerless continuation page the cost columns are taken by the page's arithmetic as left of the visits, and a column that is on most rows the sum of the visit columns before it is the table's total, not a visit. (On the saved read of the four-visit-group contract this took the rows with a page-printed total from 16 of 66 to 56 of 69.)
- **Sweep:** a `nonFee` mark drops an amount only where a rule of ours agrees (a code or page number with no currency mark, cents or thousands comma; a repeat equal to a price the master holds); anything else the model calls no fee stays asked and is counted (`modelKept`). Not built: collapsing those into one "dismissed amounts" question or the blind-sample pool (the owner chose either); they stay asked, the stricter choice.

Measured with `ocr-eval` on the saved reads (no AI; the saved reads hold no pointers, so this is the geometry change alone), strict: questions 197 to 146 on the contract with the shifted continuation pages (scan values 107 to 62, no blank-invoiceable question left); the other three unchanged (46, 148, 43); wrong values confirmed 0 on all four; every planted-error class still fully caught, the same two uncaught row swaps as before on that contract (194/196 to 196/198 with more values confirmed). Live: one full read with the first map version cost $1.33 (the read's own spend cap is a check before each call, so a read can pass it) and returned no pointers; one grid page with the final map cost $0.25. A full live read with the final map, and the second contract, are not yet run (the budget the owner set was reached).

Switches `EXTRACTION_BANDS` and `EXTRACTION_TOKEN_MAP` are still off by default. A dense grid page (30 visit columns) falls back to tiles whichever way the bands are set (`bands_fallback`, why `size`); the tiles carry the same map.
